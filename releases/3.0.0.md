# PlexonCrates 3.0.0

PlexonCrates 3.0.0 is the first production 3.0 release line, completing the existing `3.0-Update` architecture with optional PlexonCore 1.x integration and the controlled migration path required to replace PhoenixCratesLite on PlexonCraft.

## Core-native, still standalone

- Registers PlexonCrates as Core module `crates` when PlexonCore 1.x is present and compatible.
- Publishes `STARTING`, `READY`, `DEGRADED`, and `FAILED` lifecycle health while keeping crate gameplay/database ownership inside PlexonCrates.
- Runs in `STANDALONE` compatibility mode when Core is absent or incompatible.
- Keeps PlexonCore compile-only/provided; no Core runtime classes are shaded into the JAR.

## Public integration contracts

- Preserves `com.antondev.crates.api.PlexonCratesApi` through Bukkit ServicesManager in Core and standalone modes.
- Preserves the existing Bukkit event surface.
- Keeps `com.antondev.crates.api.event.CrateOpenEvent` post-success and PlexonQuests 3.1 compatible with `player()` and `plan()` plus `transactionId`, `crateId`, `keyId`, `openingCount`, `rewardIds`, and `source` metadata.
- Uses a single logical post-success crate-open event per transaction so bulk contribution uses `openingCount` rather than duplicate event emission.

## PlexonKeys 1.2

- Prefers the stable PlexonKeys 1.2 Bukkit service API for current exact physical-key templates.
- Retains the isolated compatibility adapter as fallback where required.
- Preserves last-known-good and exact configured fallback behavior; unresolved live-only definitions still fail closed.
- Does not shade PlexonKeys runtime classes into PlexonCrates.

## Existing 3.0 systems retained

- Exact Paper ItemStack snapshots and metadata fidelity.
- 10,000-basis-point percentage allocation and deterministic largest-remainder conversion.
- Versioned durable drafts, leases, takeover protection, forward undo and atomic definition publication.
- Journal-first opening correctness, exact key consumption, Claim Inbox recovery and history/statistics.
- World links, native TextDisplay presentation, animations/effects, milestones, rerolls, virtual keys and signed portable crates.
- Typed item, command, XP, level, Vault-money and mixed reward bundles.

## Phoenix replacement

PlexonCrates itself has no Phoenix runtime dependency. The migration framework treats only operator-owned Phoenix data as a source, confines migration input, hashes source files, never rewrites Phoenix files and imports definitions only through the normal draft/publication model.

The final release must only be tagged after the actual current PlexonCraft Phoenix data folder or sanitized exact fixture has been tested and all staging/cutover gates in `docs/CUTOVER.md` have passed. Unknown or ambiguous Phoenix fields must remain explicit `MANUAL_REVIEW`, `UNSUPPORTED`, or `CONFLICT` rather than being silently guessed.

## Release integrity

The GitHub release contains:

```text
PlexonCrates-3.0.0.jar
SHA256SUMS.txt
```

The release workflow runs Java 25 `clean verify`, requires all discovered tests to run, confirms SQLite JDBC is bundled, and rejects shaded PlexonCore/PlexonKeys runtime classes before publishing.

See `TESTING.md`, `MIGRATION.md`, `docs/PLEXONCORE.md`, `docs/PHOENIX_MIGRATION.md`, `docs/API.md`, and `docs/CUTOVER.md`.
