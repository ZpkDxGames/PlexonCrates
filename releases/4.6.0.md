# PlexonCrates 4.6.0

PlexonCrates 4.6.0 is a focused interaction-hot-path optimization and PlexonCore 2 compatibility release built on the mature 4.5.0 crate/opening/exact-item architecture.

## Highlights

- Compiles and release-verifies against PlexonCore 2.0.4 while retaining safe Core 1 legacy and standalone detection.
- Uses Core 2.0.4 owner-aware module state transitions and owner-scoped unregister cleanup.
- Reports `CORE_RUNTIME`, `CORE_LEGACY`, or `STANDALONE` accurately.
- Adds a hard `BLAZE_ROD` material gate before Link Wand metadata/PDC access.
- Adds a hard `CHEST` material gate before Portable Crate metadata/PDC access.
- Reuses one metadata/PDC inspection for wand marker/schema/selected-crate identity.
- Reuses one metadata/PDC inspection for portable marker/schema/token and HMAC decoding.
- Passes the already-inspected portable token into durable database verification.
- Retains the original LOWEST wand and HIGH crate interaction phases.
- Retains all linked-crate protection listeners locally.
- Preserves exact-item persistence, public crate events, key payment, opening journals, claims, milestones, rerolls, linked locations, portable authentication, and SQLite ownership.
- Generalizes release CI to immutable `v*` tags whose exact Maven version must match the tag.
- Release CI verifies Java 25 bytecode, plugin metadata, implementation version, required classes, non-shading of PlexonCore/PlexonKeys, zero skipped tests, and SHA-256 integrity.

## Core 2 interaction ownership

The PlexonCore 2 API shared event gateway exposes block-break acquisition, but not `PlayerInteractEvent` with mutable cancellation/priority parity.

For correctness, PlexonCrates 4.6 therefore keeps:

- Link Wand interaction: LOCAL
- Portable Crate interaction: LOCAL
- Linked crate preview/open: LOCAL
- Block protection: LOCAL
- Complex protection: LOCAL

This is intentional. The Core 2 module runtime is used for lifecycle/integration registration, while the interaction cost is reduced locally without changing Paper event semantics.

## Lifecycle certification

The automated Core integration suite covers:

- Core 2.0.4 compatibility;
- successful registration and final `READY` state;
- Core 1 legacy compatibility;
- Core 3 rejection;
- safe standalone loading when Core is absent;
- duplicate module ownership protection so another plugin's `crates` registration is not replaced or removed.

Real-server runtime state remains a separate deployment gate.

## Dependency baseline

- Paper 26.2
- Java 25
- PlexonCore 2.0.4
- PlexonKeys 1.3.0 public service API baseline

PlexonCrates continues to use the stable public PlexonKeys service surface rather than private Core internals.

## Upgrade

1. Back up the PlexonCrates data directory and SQLite database.
2. Install/upgrade PlexonCore to 2.0.4.
3. Use a compatible stable PlexonKeys provider.
4. Replace the previous PlexonCrates JAR with `PlexonCrates-4.6.0.jar`.
5. Start Paper 26.2 on Java 25.
6. Run `/pcrates diagnose` and verify crate/key/runtime health.
7. Test a normal linked crate, Link Wand, Portable Crate, physical-key opening, bulk/selective opening, and linked-block protection before reopening production traffic.

## Rollback

4.6.0 introduces no destructive crate database migration. If necessary, stop the server and restore PlexonCrates 4.5.0. Crates, rewards, exact items, opening state, portable signing state, and linked locations remain owned by PlexonCrates and are not migrated into Core.
