# PlexonCrates 5.0.0-rc.4 — Phase 3 Premium UX Closure

This candidate is a narrowly scoped GUI/UX correction on top of the integrated Phase 3 RC3 lineage.

## Fixed

- The existing command-driven Phase 3 Crate Hall and Preview remain unchanged and continue using the 54-slot player UX.
- Compatibility and physical linked-crate player previews now use the shared `ProbabilityPresentation` language instead of exposing the legacy probability template directly.
- Selective rewards show `Selective choice`; no random percentage is fabricated for a player choice.
- Random rewards show the readable current eligible-pool probability and distinguish configured base chance only when useful.
- Player-facing alternative/fallback presentation no longer exposes internal reward IDs or backend reason enum names.
- Selective confirmation no longer exposes source/actual internal reward IDs, backend fallback enums, or permission-node implementation detail.
- No global inventory-open interception or reopen-on-refresh behavior was introduced.

## Preserved architecture

No changes were made to `OpeningService`, payment consumption, opening journals, recovery classification, ClaimService durability, exact ItemStack custody, PlexonKeys provenance, persistence/schema logic, statistics, limits, pity, replay protection, or migration behavior.

The four historical `MANUAL_REVIEW` journal rows remain untouched.

## Verification boundary

Canonical CI and release-candidate verification must pass for the exact RC4 source before publication. Runtime certification is not performed by this pipeline; the published artifact must be handed to Runtime Pipeline 7.
