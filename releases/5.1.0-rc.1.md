# PlexonCrates 5.1.0-rc.1 — Full Source Hardening

This release candidate is the runtime-certification boundary for the PlexonCrates 5.1 full-source revamp. It is based directly on stable `v5.0.0` and preserves the existing opening transaction, exact-item, durable recovery, claim, publication, PlexonKeys and SQLite schema-4 product model.

## Hardened GUI lifecycle

- Player menu sessions now have explicit ownership and deterministic close/quit cleanup.
- Accepted view-changing inventory actions are deferred to the next server execution point and revalidated against the exact active holder/session/revision before navigation or mutation.
- `CrateMenuEventRouter` is the single registered click/drag authority for crate menu surfaces.
- Test Lab click/drag handling is routed through that central authority while editor-open decoration remains isolated to `InventoryOpenEvent`.
- Stale async simulation/menu output fails closed instead of replacing a newer view.

## Scheduler and executor hardening

- Roulette animation uses one shared `OpeningAnimationCoordinator` rather than one repeating Bukkit task per opening.
- Plugin-owned general I/O uses a bounded executor with explicit shutdown.
- Opening-log writes use a bounded queue with rejection handling.
- Crate simulation remains a bounded, non-granting analysis worker and is explicitly closed on disable.

## Administrative I/O hardening

- Live reload loads canonical definitions/drafts/keys asynchronously, performs file/YAML preparation off-thread, and applies only the validated state swap on the primary thread.
- Live validation, diagnostics and post-reload PlexonCore health probes no longer perform their heavy reads on the primary thread.
- Optional published/draft/key YAML mirrors are non-authoritative and persist away from the gameplay thread.
- Live key mutation, crate creation/import/deletion/transfer and related admin operations have explicit file/database I/O boundaries.

## Phoenix migration hardening

- Scan, hash, parse, plan, validate and report work runs on bounded I/O workers using immutable primary-thread snapshots where Bukkit/plugin state is needed.
- Destructive import is staged across worker and primary-thread phases rather than moving Bukkit/world/registry mutation off-thread.
- Backup, database/history/location persistence and report generation remain outside the primary-thread activation stages.

## Release safety

- Build provenance is anchored to rollback release `v5.0.0` / `f24e3f7f942f7c886352e71c7105af499828096f` and CI proves that exact tag/SHA ancestry.
- A dedicated prerelease workflow rebuilds, verifies, publishes and re-downloads the exact RC artifact before accepting publication.
- Stable publication now requires a checked-in runtime-certification PASS record tied to a published RC tag, source SHA and JAR SHA-256.
- Stable promotion rejects production-code drift after the certified RC; only narrowly scoped promotion metadata/version files may differ.

## Verification before publication

The source-hardening boundary passed canonical CI with 267 tests before the release-policy tests were added. RC1 publication must pass the complete current test suite, distribution checks, Java 25/class-major verification, Paper 26.2 contract, dependency-shading checks, provenance generation, whitespace validation and post-publication asset checksum verification from the exact RC source.

## Runtime certification required

`5.1.0-rc.1` is a prerelease and must not be promoted to stable until the exact published JAR passes the real PlexonCraft Paper 26.2 gates:

- clean enable, disable and restart;
- Crate Hall and all player opening flows;
- physical and portable crates;
- selective/bulk openings, Pending Rewards and rerolls;
- admin editor, Test Lab, publish, reload, backup, validate and diagnose;
- schema-4 persistence/restart with no duplicate grant or data loss;
- Phoenix migration smoke where a suitable source is available;
- active-use spark comparison against the accepted 5.0 baseline.

`v5.0.0` remains the rollback release until those gates pass.
