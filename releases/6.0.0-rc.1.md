# PlexonCrates 6.0.0-rc.1

## Runtime certification candidate

PlexonCrates 6.0.0-rc.1 is the source-complete release candidate for the full GUI, animation-profile, and exact-item administration revamp.

This prerelease is **not stable promotion**. Its GitHub provenance must record `runtime_certification=NOT_EXECUTED`, and the exact published JAR must pass real PlexonCraft Paper 26.2 runtime/performance certification before `v6.0.0` may be published.

## Player product flow

- Retains the canonical Crate Hall -> preview -> confirmation -> authoritative opening path.
- Adds paginated **My Keys** using authoritative physical, PlexonKeys-wallet, and local virtual-wallet balances.
- Adds paginated **Opening History** backed by asynchronous history loading with loading/error/empty/refresh states and crate-preview navigation.
- Retains the durable Claim Inbox for exact overflow/recovery deliveries.
- Keeps physical and portable crate interactions on the same opening/payment/recovery services as GUI/command openings.

## Opening animation profiles

- Adds reusable styles: `INSTANT`, `ROULETTE`, `SPIN`, `CHARGE_REVEAL`, `SPIRAL_BURST`, `ORB_REVEAL`, `CASCADE`, and `FIREWORK_STYLE`.
- Adds explicit `START`, `CHARGE`, `SELECTION`, `REVEAL`, `CELEBRATION`, and `FINISH` stages.
- Adds validated particle/sound/volume/pitch/range/particle-budget/summary controls.
- Adds `animations.yml` with named profiles plus global/per-crate assignment.
- Uses reserved `legacy` inheritance by default so an upgrade does not silently change existing 5.x crate animation behavior.
- Adds an in-game profile editor with style/stage/effect controls, clone/reset, global/per-crate assignment, and legacy inheritance.
- Production and Test Lab use the same shared profile presentation renderer.
- Preserves one shared opening-animation scheduler; no repeating task is created per opening, player, or profile.

## Physical idle profiles

- Adds named `idle-animations.yml` profiles for `NONE`, `SPARKLE`, `RING`, `DOUBLE_RING`, `ORBIT`, `HELIX`, `PULSE`, `RISING`, and `AURA`.
- Adds per-profile particle, geometry, receiver range, per-crate budget, and per-viewer budget controls.
- Uses reserved `legacy` inheritance by default to preserve existing `particles.*` behavior from `config.yml`.
- Resolves an effective idle profile per linked crate while retaining one shared receiver-scoped particle coordinator.
- Existing global location/particle ceilings remain the master runtime safety bounds.
- Adds a crate-scoped idle-profile editor and one-frame preview capped at 256 particles without creating a preview scheduler.

## Exact-item administration

- Keeps native Paper ItemStack bytes as the canonical exact-item source.
- Expands `ExactItemInspector` diagnostics for byte size, SHA-256 fingerprint, custom-data/container flags, amount, and maximum stack size.
- Physical Key administration fingerprints the resolved exact key template rather than a cosmetic menu icon.
- Reward Builder keeps exact capture slots untouched and exposes diagnostics through a separate read-only companion control.
- Global reward browsing uses presentation copies while diagnostics inspect exact delivery copies.
- Test Lab exact-item audit displays an untouched clone separately from diagnostics.
- Adds regression tests proving diagnostic presentation does not rewrite source ItemStacks.

## Test Lab / administration

- Retains the existing Admin Dashboard and Crate Studio authorities instead of creating a duplicate control plane.
- Adds publication/readiness, deterministic dry selection, bounded simulation, configured/player probability modes, worker diagnostics, exact-item audit, profile-aware opening preview, and physical idle-profile preview.
- Test Lab remains non-granting/non-consuming and cannot finalize opening/payment/statistics state.
- GUI click/drag authority remains centralized through `CrateMenuEventRouter`.

## Preserved transaction and storage boundaries

6.0 does not rewrite or move:

- `OpeningService` transaction authority;
- journal/payment/revalidation/grant ordering;
- reward selection, limits, pity, cooldown, milestones, and rerolls;
- claim/recovery/manual-review behavior;
- PlexonKeys provider/payment provenance;
- durable draft/publication revisions;
- portable signing/issuance/replay protection;
- Phoenix migration boundaries;
- SQLite canonical state.

SQLite remains schema `4`.

## Compatibility

- Paper: `26.2.build.121-stable`
- Java: `25`
- PlexonCore: `2.0.4` provided/optional integration
- PlexonKeys API baseline: `2.0.0-rc.2` provided dependency
- Stable rollback: `v5.0.0` / `f24e3f7f942f7c886352e71c7105af499828096f`

`animations.yml` and `idle-animations.yml` are new presentation-only registries. Their bundled `global-profile: legacy` defaults preserve existing behavior until an administrator deliberately opts into named profiles.
